# 服务中心

用户入口为“服务中心”，包含新手接入、五小时限额和号池总览。管理员“服务管理”分为五小时限额、用户与账号、Discord、引导与订阅、重置监测五个标签页；旧 `/onboarding`、`/5h-pressure` 及管理员旧地址仍兼容。

新用户从 Discord 登录或注册后，在服务中心完成三步：添加 GPT 账号、创建或选择 API Key、下载 CC Switch 并通过内置导入功能配置来源。切换至该来源后重启 Codex。管理员需先配置 Discord 应用、机器人、模板账号和订阅分配规则。

站点登录和注册仅使用 Discord。系统只接受 Discord 返回的已验证邮箱，并按该邮箱匹配站内用户；Discord ID 不用于选择登录用户。首次登录会自动保存绑定、加入指定服务器并授予配置的身份组。若 Discord 邮箱与站内邮箱不一致，请由管理员修改站内邮箱后重新登录；服务中心不再显示单独的 Discord 步骤。

已有可用的 OpenAI API Key 时，第二步直接标记完成，无需重复创建；有多个 Key 时，按 Key 名称和分组名称选择，第三步使用所选 Key 导入 Codex。已停用、已到期、额度耗尽或分组不可用的 Key 不可导入。已有 Key 加载失败时会显示重试入口。

管理员按用户邮箱分配 GPT 账号，也可搜索服务器中已有的 Discord 成员并绑定，操作前会显示双方身份进行确认。用户可查看自己的账号详情、暂停、恢复或删除账号。所有接入账号均可回退公共池，优先服务所属用户，无需额外勾选。重复接入同一 GPT 身份会被拒绝。

暂停或删除账号会暂停失去资格的自动订阅；恢复账号仅在原有效期内恢复订阅，不延长有效期或清空用量。手动授予、购买的订阅以及管理员手动暂停的订阅不受自动恢复影响。

OAuth 授权失效时，在自己的账号行点击“重新授权”，核对弹窗中的 GPT 名称和邮箱，使用原账号、原工作区登录并粘贴完整回调链接。localhost 页面无法打开不影响复制地址栏链接。后端校验账号归属、GPT 工作区及用户身份，授权状态还绑定当前用户、目标账号与本次 OAuth 会话。成功后更新原账号令牌、清除授权错误并在事务提交后刷新令牌缓存；保留调用规则、账号名称、归属、管理员停用及用户暂停状态，不创建重复账号、不重置订阅用量或延长原有效期。此流程沿用原账号代理，不依赖新账号模板；仍需保持 Discord 绑定有效。

## 账号数量与订阅

管理员分别为 1、2、3、4、5 个及以上 Plus 等值设置一个 OpenAI 订阅分组和有效期。先合计用户所有有效账号的等值数量，再匹配一个档位，不叠加多个自动订阅。未配置的档位不自动分配，也不回退到较低档位。

| 账号套餐 / OAuth 标识 | Plus 等值 |
| --- | --- |
| Plus | 1 |
| Business Standard（`team`、`self_serve_business_usage_based`） | 1 |
| Pro 5x（`prolite`）、Business Premium（`self_serve_business_prolite`） | 5 |
| Pro 20x（`pro`）、Pro 50x（`promax`） | 20、50，均匹配 5 个及以上档位 |
| Free、Enterprise（`business`）或未知套餐 | 不计入 |

例如两支 Plus 匹配“2 个 Plus 等值”；一支 Pro 5x 或 Business Premium 匹配“5 个及以上”；暂停第三支 Plus 后从 3 个等值重新匹配到 2 个。暂停、过期或异常的账号不计入有效数量。

旧版本按套餐分配的规则会转换为数量档位；若同一档位对应不同订阅或有效期，该档位会留空并提示管理员重新选择。升级后请在“服务管理 → 引导与订阅”检查五个档位并确认保存。

## 指定账号模板

在“服务管理 → 引导与订阅 → 新账号调用规则”按 GPT 账号名称和邮箱选择一个 OpenAI OAuth 母账号。新用户接入时复制该模板的模型映射、模型限制、调度阈值、错误处理、WebSocket、透传、压缩、客户端限制、自动暂停/用券规则，以及代理、并发、优先级、负载因子、计费倍率和分组。自动订阅对应的分组仍按用户贡献档位补充。

新账号使用自己的 OAuth 令牌、GPT 身份和套餐，不继承模板的到期时间、所属用户、用量、重置券、指纹种子、异常或暂停状态。模板后续变更只影响之后接入的账号。未指定模板或模板已删除时，授权入口会提示管理员完成配置，不会静默使用另一支账号。

## 全池重置联动

重置监测读取 Discord 频道的新消息及 embed 更新，使用站内号池模型分析，替代账号池轮询推断和 Gmail 邮件监测。账号自身的窗口更新与自动用券继续按原设置运行。

在“服务管理 → Discord”配置机器人和服务器；机器人在监测频道需要“查看频道”和“读取历史消息”权限，在通知频道需要发送消息权限。默认来源频道为 `1561630415750561863`，必须属于配置的服务器。在 Discord Developer Portal 为机器人启用 Message Content Intent，必要时按 Discord 要求申请批准；REST 返回的 embed 也可能受此权限影响。若收到的 embed 为空，不会分析或触发，请核对机器人实际可读取的内容。无需 Gmail 授权。

在“重置监测”中选择当前管理员自己的站内 API Key 和号池模型，保存后再启用全员配额重置并保存服务配置。模型请求固定使用本站 Responses 接口，只发往本服务的回环地址，沿用所选 Key 的分组、调度、模型映射、计费及限额，不提供外部模型 URL、外部密钥或接口格式设置。默认模型采用项目现有的测试模型 `gpt-5.4`，可按号池实际支持的模型修改；需要保证监测 Key 在尖峰时也有可用额度。

| 参数 | 默认值 |
| --- | --- |
| 频道检查间隔 | 300 秒（5 分钟），每轮结束后计时，多实例共用；最短 60 秒 |
| 额外等待 | 0 分钟，任一来源确认后立即处理；可按实际到账延迟调整 |
| 执行后防重复 | 720 分钟（12 小时），不得短于传播等待和 2 小时合并窗口 |
| 重置券发放 | 默认处理已确认的发券，可单独关闭 |
| 高级设置 | 作者 / Webhook ID 白名单、模型补充规则，默认收合 |

频道、站内 Key、模型和表中业务选项可修改。已确认的直接重置始终处理，整体启停仍由全员配额重置开关控制。以下技术保障固定，不再提供设置项：只处理含 embed 的机器人 / Webhook 消息、2 小时事件合并窗口、24 小时消息时效、最低置信度 0.95、每轮最多分析 20 条、同一内容最多尝试 3 次、模型超时 60 秒、输出上限 2048 token、正文上限 24000 字符、判定记录保留 30 天。内置判断规则始终生效，补充规则可留空。

机器人读取文字与 embed 的标题、描述、字段、作者及页脚；不会访问 embed 链接或下载附件。只把匹配来源的文字发送到站内号池，数据库不保存完整正文。消息 ID 与内容摘要共同去重：相同内容不重复分析，先发空壳后补 embed、或预测通知更新为确定重置时可重新判断。

通知样本中，确认事件大多相隔约 1～4 天，也有连续两天的确认；两个来源的同批确认曾相差 29 分钟。通知间隔不能证明账号传播需要 29 分钟，因此默认收到确认后不额外等待，也不要求两个来源同时发出确认；采用较低检查频率和 12 小时防重复，不按固定天数自动重置。升级时清理废弃参数，将旧默认的 5 秒检查 / 15 或 30 分钟等待 / 6 小时防重复更新为 5 分钟检查 / 0 分钟等待 / 12 小时防重复；其他自定义值保留，仅将不足 60 秒的检查间隔及过短的防重复时间提高至有效下限。已保存的 Key、模型、频道、去重记录、待处理事件和冷却不会清空，已有待处理事件保留原执行时间。

| 证据或场景 | 行为 |
| --- | --- |
| 任一来源明确“已经重置”，置信度 0.99，逐字原文依据通过 | 默认当轮处理时执行一次，不等另一来源 |
| 明确“已发放 banked reset / reset credit” | 默认触发，可单独关闭 |
| `probability alert`（即使 99% / 100%）、`Possible Codex reset by`、未来的 `Codex reset announced by` | 不触发 |
| 14:46 与 15:15 的两来源确认通知 | 首条确认处理时执行；第二条合并，不再执行 |
| 空 embed 后来补全 | 下一轮读取后分析，不因最初为空而永久跳过 |
| 同一消息的 embed 内容发生变化 | 新内容可重新分析，仍受事件合并和冷却约束 |
| 已执行后重复通知，或冷却期消息延迟到冷却结束才读取 | 不重复执行 |
| 次日出现新的确认通知，已超过防重复时间 | 作为新事件，默认当轮执行 |
| 积压中出现超出合并窗口的新事件 | 新事件替代旧待处理事件，仅恢复一次；等待时间按配置计算 |
| Key 无额度、模型错误、依据非原文、低置信度 | 不触发；模型失败最多尝试 3 次并保留结果 |
| 启用前、换频道前或过期的通知 | 不补触发 |
| 修改监测配置或启停检测 | 取消旧待处理事件，保留已生效冷却 |
| 重启、多实例并发 | 数据库去重、带所有权令牌的锁及事务阻止重复清零 |
| Discord 429 | 按服务端要求延后检查，不连续重试 |

模型判断无法证明八支账号已经全部到账，实际执行还受检查间隔和分析耗时影响；如观察到确认通知后仍有账号未到账，可另设额外等待。频道专用于通知时效果更稳定；每轮最多回看 1000 条，超出后会提示使用专用频道。模型不可用或仍有待分析积压时暂缓执行；失败内容达到尝试上限后不再阻塞其他通知。

确认后的事务会写入事件，清零所有用户仍在有效期内的活动 / 暂停订阅日、周、月用量，并建立滚动五小时统计的新起点。包含手动授予和购买的有效订阅；保留订阅状态、起止时间、原始使用记录和历史审计。旧消费仍保留在账单中，不再占用重置后的五小时额度。非尖峰行为保持不变。

消息去重、待处理事件、冷却、全局统计起点及通知待办持久化在 PostgreSQL。配额与事件在同一事务提交，重启后可补做缓存失效。缓存处理成功后向通知频道发送保存的原文，支持 @everyone、@here、`<@用户ID>` 和 `<@&身份组ID>`；机器人需有相应权限。

Discord 通知使用持久化领取状态和固定 nonce。明确限流时稍后重试；超时、服务器异常、发送中崩溃等结果不确定的情况显示待核对，避免自动重复发送。通知失败不会回滚或再次重置配额。

## 五小时规则

用户五小时限额页显示平滑/即时压力、尖峰门槛、容量、消耗和需求估计。账号池平均 5h / 7d 容量已移至“号池总览”，同时列出全部账号的窗口用量和剩余时间。无数据与 0% 分开显示，账号名称中的邮箱隐藏，不公开账号 ID、凭据或原始错误。平均值不是套餐加权容量，也不改变个人额度。

基础额度 = 所有有效订阅的周美元额度之和 × 15%。消费取 sub2api 使用记录的实际计费金额 `actual_cost`，包含模型价格与计费倍率，按用户合计最近五小时的已记录消费。未设置正周额度的订阅不参与求和；没有可用周额度时不执行额外五小时限流。

保留原有压力判定：默认压力达到 100% 进入尖峰，低于 90% 退出（已有配置可覆盖）。只有尖峰且个人消费达到额度时才限制新请求。非尖峰持续统计消费，但不执行额外五小时限流。原有订阅、账号及 API Key 限制继续生效。

例如有效订阅周额度合计 $100，则五小时额度为 $15：

| 场景 | 结果 |
| --- | --- |
| 非尖峰，五小时消费 $20 | 显示 133.3%，仍可继续使用 |
| 进入尖峰，消费 $14 | 仍可使用，剩余 $1 |
| 尖峰，消费恰好 $15 或更多 | 限制后续新请求 |
| 已限流，压力回落至 90% | 仍在尖峰；低于 90% 才退出 |
| 退出尖峰，消费仍为 $20 | 立即解除额外限流 |
| 同样用量使用价格更低的模型 | 实际计费较少，额度消耗更慢 |
| 其他用户大量使用 | 可能改变尖峰状态，不改变你的消费和额度 |
| 停止使用 | 随旧记录移出五小时窗口，用量持平或下降；订阅变更会改变额度 |
| 管理员设置豁免 | 尖峰时也不执行额外限流 |
| 管理员重置用量 | 只统计重置之后的记录，保留原始使用记录与审计 |
| 有效订阅分别为 $60 和 $40/周 | 合计额度仍为 $15/5h |
| 重启服务或 Redis 清空 | 直接从数据库使用记录和重置审计恢复；不依赖 Redis 保存个人用量 |
| 压力数据过期或读取额度失败 | 暂停额外限流，不中断原有计费 |

“预计恢复”表示在没有新消费、订阅额度不变时，旧消费过期后低于额度的最早时刻。非尖峰仍可继续消费，所以该时刻可能后移。已放行的并发请求及异步入库延迟可能使最终用量超过 100%；不会中断已放行的请求。

## 代码组织

用户入口为 `ServiceCenterView.vue`，管理员入口为 `ServiceManagementView.vue`；接入引导和管理设置分别放在服务组件目录，通用窗口条使用 `UsageWindowBar.vue`，同时支持 5h / 7d。服务中心 API 与基础用户 API 分离，后端入口为 `ServiceCenterService` / `ServiceCenterHandler`，`dynamic_5h_*` 仅负责五小时压力与限流。

已发布的 `/onboarding` API、数据库表名、OAuth 状态字段及历史迁移文件继续保留原名，以兼容已部署数据和旧地址。
